# E16-S12: Modify Pending Order

**Epic:** E16 — Web UI  
**Phase:** P3 (Web UI improvements)

## Description

Pending orders cannot be edited from the UI. Users need to change the limit price, stop loss, or take profit of a pending order without cancelling and recreating it. Add a Modify form on the order history page (E16-S11) for each `pending` order row.

## File Locations

- `src/phantom/web/routes/orders.py` — add `POST /orders/{order_id}/modify`
- `src/phantom/web/templates/order_history.html` — add modify form per pending row

## Current State

- `ph.orders` has no `modify()` method — this needs to be added to `src/phantom/api/orders.py` and the underlying `src/phantom/db/repositories/order_repo.py`
- Order fields that can change: `limit_price`, `stop_loss`, `take_profit`
- Order model is `src/phantom/models/order.py`

## Acceptance Criteria

- [ ] `OrderAPI.modify(order_id, limit_price=None, stop_loss=None, take_profit=None)` is added — raises `ValidationError` if order is not `pending`, raises `ValidationError` if no fields provided
- [ ] `order_repo` gets `update_prices(order_id, updates: dict)` using parameterised SQL
- [ ] `POST /orders/{order_id}/modify` accepts `limit_price`, `stop_loss`, `take_profit` form fields (all optional), redirects to `/orders?account=<name>` on success
- [ ] Each pending row in `order_history.html` has an expandable `<details>` modify form pre-populated with current values
- [ ] Submitting with all fields blank returns an inline error ("Provide at least one field to modify")

## Implementation Notes

**`order_repo.py`** — add method:

```python
def update_prices(self, order_id: str, updates: dict) -> Order:
    # updates keys: limit_price, stop_loss, take_profit (any subset)
    set_clauses = ", ".join(f"{k} = ?" for k in updates)
    values = list(updates.values()) + [to_iso(now_utc()), order_id]
    self._conn.execute(
        f"UPDATE orders SET {set_clauses}, updated_at = ? WHERE id = ?",
        values,
    )
    self._conn.commit()
    return self.get(order_id)
```

**`api/orders.py`** — add method:

```python
def modify(self, order_id: str, limit_price=None, stop_loss=None, take_profit=None) -> Order:
    with self._lock:
        order = self._order_repo.get(order_id)
        if order.status != "pending":
            raise ValidationError(f"Cannot modify order with status '{order.status}'")
        updates = {}
        if limit_price is not None:
            updates["limit_price"] = limit_price
        if stop_loss is not None:
            updates["stop_loss"] = stop_loss
        if take_profit is not None:
            updates["take_profit"] = take_profit
        if not updates:
            raise ValidationError("Provide at least one field to modify")
        return self._order_repo.update_prices(order_id, updates)
```

**`orders.py`** web route:

```python
@router.post("/orders/{order_id}/modify")
async def modify_order(
    order_id: str,
    account: str = Form(...),
    limit_price: float | None = Form(None),
    stop_loss: float | None = Form(None),
    take_profit: float | None = Form(None),
):
    try:
        ph = get_phantom()
        ph.orders.modify(order_id, limit_price=limit_price, stop_loss=stop_loss, take_profit=take_profit)
        return RedirectResponse(url=f"/orders?account={account}", status_code=303)
    except PhantomError as e:
        return RedirectResponse(url=f"/orders?account={account}&error={e}", status_code=303)
```
