# E13-S02: Tick State Persistence

**Epic:** [E13: Paper Trade Scheduler](e13-paper-trade-scheduler.md)
**Phase:** P2
**Depends on:** [E13-S01](e13-s01.md)

## Description

After each scheduler tick completes, commit all pending position, order, and equity changes to the database inside a single atomic transaction. The tick wrapper must use a `try/except` block: if the tick raises any exception, log at ERROR level with the exception details and continue — the scheduler must never crash due to a single bad tick. On exception, roll back the connection so no partial state is written. This ensures the live paper trade session is resilient to transient data feed errors or unexpected market edge cases without requiring manual restart.

## File Locations

- `src/phantom/engine/scheduler.py` — `_run_tick()` wrapper method on `PaperTradeScheduler`

## Acceptance Criteria

- [ ] The APScheduler job target is a `_run_tick()` wrapper, not `engine.run_paper_tick()` directly
- [ ] `_run_tick()` wraps the engine call in `try/except Exception` and logs with `logger.error("Paper trade tick failed: %s", e, exc_info=True)`
- [ ] On success, `_run_tick()` calls `self._conn.commit()` exactly once to flush all pending writes atomically
- [ ] On exception, `_run_tick()` calls `self._conn.rollback()` before returning so no partial state leaks
- [ ] Unit test: patching the engine to raise `RuntimeError` does not propagate out of `_run_tick()`
- [ ] Unit test: successful tick calls `conn.commit()` exactly once and does not call `conn.rollback()`

## Implementation Notes

```python
def _run_tick(self) -> None:
    try:
        self._engine.run_paper_tick()
        self._conn.commit()
    except Exception as e:
        logger.error("Paper trade tick failed: %s", e, exc_info=True)
        self._conn.rollback()
```
