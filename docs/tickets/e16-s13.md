# E16-S13: Partial Close Position

**Epic:** E16 — Web UI  
**Phase:** P3 (Web UI improvements)

## Description

The existing close action (E16-S09) closes a position entirely. For manual backtesting it is common to reduce exposure by closing a fraction of a position (e.g., close 50 of 100 shares). Add a quantity field to the close form so users can specify how many units to close.

## File Locations

- `src/phantom/api/positions.py` — extend `close()` to accept `quantity`
- `src/phantom/web/routes/positions.py` — update `POST /positions/{position_id}/close`
- `src/phantom/web/templates/position_detail.html` — add quantity field
- `src/phantom/web/templates/_positions_rows.html` — add quantity field to inline close form

## Current State

`PositionAPI.close(position_id, close_reason, exit_price)` closes the full position. Internally it calls `manager.close(position, exit_price, close_reason, now_utc())` which creates an exit `Order` record for `position.quantity` units.

The `PositionManager.close()` in `src/phantom/engine/position_manager.py` should be checked for its signature before modifying the API layer.

## Acceptance Criteria

- [ ] `PositionAPI.close()` gains an optional `quantity: float | None = None` parameter
- [ ] If `quantity` is `None` or equals `position.quantity`, existing full-close behaviour is unchanged
- [ ] If `quantity < position.quantity`, the position's quantity is reduced by that amount; a new closed sub-position is NOT created — instead, `position.quantity` is decremented and the partial exit is recorded as a cost entry. Cash is credited for `quantity * exit_price - exit_costs`
- [ ] If `quantity > position.quantity`, raise `ValidationError("Quantity exceeds open position size")`
- [ ] The close form on the position detail page and dashboard row has a "Quantity to close" field pre-populated with the full quantity
- [ ] Closing 0 units raises `ValidationError("Quantity must be greater than zero")`

## Implementation Notes

Partial close approach — simplest path that avoids creating new entities:

1. Compute `exit_costs` proportionally: `costs_per_unit = total_entry_cost / position.quantity`, so `exit_costs ≈ cost_engine.exit_costs(position, exit_price) * (quantity / position.quantity)`
2. Decrement `position.quantity -= quantity`
3. Credit `account.cash += quantity * exit_price - exit_costs`
4. If `position.quantity == 0` after decrement, mark status `"closed"`, set `exit_datetime`, `exit_price`, `realized_pnl`
5. Otherwise keep status `"open"`, update `realized_pnl += (exit_price - position.entry_price) * quantity - exit_costs`

Check `src/phantom/engine/position_manager.py` for the actual `close()` signature — it may already handle partial closes. If so, just pass `quantity` through the API layer.

**Web form** — add to the close `<details>` in `_positions_rows.html` and `position_detail.html`:

```html
<input type="number" name="quantity" step="0.0001" min="0.0001"
       value="{{ position.quantity }}" placeholder="Qty to close" required>
```

Pass `quantity: float = Form(...)` in the route handler and forward to `ph.positions.close(position_id, exit_price=exit_price, quantity=quantity)`.

---

> **Implementation Standards:** All cash accounting goes through the account repo `update()`. Never mutate cash directly on the model. Validate quantity > 0 and quantity ≤ position.quantity at the API layer, not just the UI.
