# E16-S16: P&L Summary Panel on Dashboard

**Epic:** E16 — Web UI  
**Phase:** P3 (Web UI improvements)

## Description

The dashboard shows cash, equity, and unrealized P&L but has no summary of realized performance: total realized P&L, number of trades, win rate, average winner, and average loser. Add a "Performance Summary" card to the dashboard pulling from `ReportAPI.account_metrics()`.

## File Locations

- `src/phantom/web/routes/dashboard.py` — call `ph.reports.account_metrics()` and include in context
- `src/phantom/web/templates/dashboard.html` — add Performance Summary card

## Current State

`ph.reports.account_metrics(account_name)` returns a dict with optional keys:
- `"trades"` — from `calculate_trade_metrics()` in `src/phantom/reports/metrics.py`
- `"equity"` — equity curve metrics (total return, CAGR, drawdown)
- `"costs"` — aggregate cost summary

The `"trades"` dict contains: `trade_count`, `win_rate`, `avg_win`, `avg_loss`, `profit_factor`, `expectancy`, `total_realized_pnl`.

These keys may be absent if there are no closed trades — always use `.get()`.

## Acceptance Criteria

- [ ] `dashboard.py` calls `ph.reports.account_metrics(account_obj.name)` and passes the result as `report` in context
- [ ] If `report.get("trades")` is empty/absent, the card shows "No closed trades yet."
- [ ] Otherwise the card shows: Total Realized P&L, Trade Count, Win Rate (%), Avg Win, Avg Loss, Profit Factor
- [ ] Positive total P&L uses `.positive` CSS class; negative uses `.negative`
- [ ] Win rate is shown as a percentage with one decimal (e.g., `62.5%`)
- [ ] The `account_metrics` call is wrapped in try/except — dashboard must not crash if reporting fails

## Implementation Notes

**`dashboard.py`** — add after building context:

```python
report = {}
try:
    report = ph.reports.account_metrics(account_obj.name)
except Exception:
    pass
# add to context: "report": report
```

**`dashboard.html`** — new card:

```html
<div class="card">
  <h2>Performance Summary</h2>
  {% set trades = report.get("trades") if report else None %}
  {% if not trades %}

  {% else %}
    <div class="summary-grid" style="grid-template-columns: repeat(3, 1fr);">
      <div class="summary-card">
        <div class="label">Realized P&L</div>

          {{ "%.2f"|format(trades.total_realized_pnl) }}
        </div>
      </div>
      <div class="summary-card">
        <div class="label">Trades</div>
        <div class="value">{{ trades.trade_count }}</div>
      </div>
      <div class="summary-card">
        <div class="label">Win Rate</div>
        <div class="value">{{ "%.1f"|format(trades.win_rate * 100) }}%</div>
      </div>
      <div class="summary-card">
        <div class="label">Avg Win</div>
        <div class="value positive">{{ "%.2f"|format(trades.avg_win) }}</div>
      </div>
      <div class="summary-card">
        <div class="label">Avg Loss</div>
        <div class="value negative">{{ "%.2f"|format(trades.avg_loss) }}</div>
      </div>
      <div class="summary-card">
        <div class="label">Profit Factor</div>
        <div class="value">{{ "%.2f"|format(trades.profit_factor) }}</div>
      </div>
    </div>
  {% endif %}
</div>
```

Check `src/phantom/reports/metrics.py` for the exact keys returned by `calculate_trade_metrics()` before implementing — the key names above are based on the existing reporting code.

---

> **Implementation Standards:** Never let the report call crash the dashboard — always wrap in try/except. Use `.get()` on all report dict access; absent keys mean no data, not a bug.
