# E7-S05: TP/SL Ambiguity Handling

**Epic:** [E7: Position System](e07-position-system.md)
**Phase:** MVP
**Depends on:** [E7-S04](e07-s04.md)

## Description

When a single price bar crosses both the take-profit and the stop-loss level, the outcome is ambiguous (we don't know which was hit first intrabar). Implement three configurable resolution strategies.

## File Locations

- `src/phantom/engine/position_manager.py` — `resolve_tp_sl_conflict()` function
- `src/phantom/config.py` — `TP_SL_CONFLICT_MODE` setting (default: `"conservative"`)

## Acceptance Criteria

- [ ] `resolve_tp_sl_conflict(position, bar, mode) -> str` returns `"tp"` or `"sl"`
- [ ] `"conservative"`: always returns `"sl"` (worst case for trader)
- [ ] `"optimistic"`: always returns `"tp"` (best case)
- [ ] `"proximity"`: returns whichever of TP/SL is closer to `bar["Open"]` in absolute price distance
- [ ] Default mode is `"conservative"` (read from config)
- [ ] Called only when both `bar["High"] >= take_profit` and `bar["Low"] <= stop_loss` are true simultaneously
- [ ] Unit tests for all three modes
