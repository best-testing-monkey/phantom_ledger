# E6-S14: Order Rejection Reasons

**Epic:** [E6: Order System](e06-order-system.md)
**Phase:** P2
**Depends on:** [E6-S03](e06-s03.md), [E6-S13](e06-s13.md)

## Description

Store a human-readable `rejection_reason` on rejected orders and set `status = "rejected"` instead of raising an exception when validation fails during automated order placement (e.g. from a strategy). Manual CLI order placement may still raise exceptions for immediate user feedback.

## File Locations

- `src/phantom/engine/order_manager.py` — `place_or_reject()` variant
- `src/phantom/models/order.py` — `rejection_reason` already in model

## Acceptance Criteria

- [ ] `place_or_reject(account_id, order) -> Order` catches validation errors and returns order with `status="rejected"` and `rejection_reason` set (rather than raising)
- [ ] `rejection_reason` values: `"insufficient_funds"`, `"insufficient_margin"`, `"outside_trading_hours"`, `"unsupported_instrument"`
- [ ] Rejected orders are persisted to DB with `status="rejected"`
- [ ] CLI `order place` still raises exceptions (uses `place()` not `place_or_reject()`)
- [ ] Strategy automation (E15) uses `place_or_reject()`
