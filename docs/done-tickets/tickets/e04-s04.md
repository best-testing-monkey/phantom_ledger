# E4-S04: DataProvider Protocol

**Epic:** [E4: Data Layer](e04-data-layer.md)
**Phase:** MVP
**Depends on:** [E4-S01](e04-s01.md)

## Description

Define the `DataProvider` Protocol so that the engine code can depend on an abstraction rather than `HistoricalProvider` directly. This enables swapping in a `LiveProvider` (P2) or a test mock without changing engine code.

## File Locations

- `src/phantom/data/provider.py` — `DataProvider` Protocol

## Acceptance Criteria

- [ ] `DataProvider` Protocol in `src/phantom/data/provider.py` with 4 methods: `get_bars`, `get_current_price`, `get_bid_ask`, `get_dividends`
- [ ] `get_bars(ticker: str, start: datetime, end: datetime) -> pd.DataFrame`
- [ ] `get_current_price(ticker: str) -> float`
- [ ] `get_bid_ask(ticker: str) -> tuple[float, float] | None`
- [ ] `get_dividends(ticker: str, start: datetime, end: datetime) -> list` (return type will be refined when `DividendEvent` model exists)
- [ ] `HistoricalProvider` structurally satisfies the `DataProvider` protocol (no explicit inheritance needed — Python structural subtyping)
- [ ] Engine and simulation code uses `DataProvider` type hints, not `HistoricalProvider`
