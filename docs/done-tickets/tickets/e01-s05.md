# E1-S05: API Module Skeleton

**Epic:** [E1: Project Scaffolding](e01-scaffolding.md)
**Phase:** MVP

## Description

Create the `src/phantom/api/` package with stub files for every sub-API, the top-level `Phantom` facade class, and the full exception hierarchy in `src/phantom/errors.py`. All methods should raise `NotImplementedError` at this stage — they will be filled in by later stories.

## File Locations

- `src/phantom/errors.py` — exception hierarchy
- `src/phantom/api/__init__.py` — package marker
- `src/phantom/api/client.py` — `Phantom` facade class
- `src/phantom/api/accounts.py` — `AccountAPI` stub
- `src/phantom/api/orders.py` — `OrderAPI` stub
- `src/phantom/api/positions.py` — `PositionAPI` stub
- `src/phantom/api/notes.py` — `NoteAPI` stub
- `src/phantom/api/data_api.py` — `DataAPI` stub
- `src/phantom/api/brokers.py` — `BrokerAPI` stub
- `src/phantom/api/reports.py` — `ReportAPI` stub
- `src/phantom/api/runner.py` — `RunnerAPI` stub

## Acceptance Criteria

- [ ] `src/phantom/errors.py` contains `PhantomError` and all 6 subclasses (`NotFoundError`, `InsufficientFundsError`, `MarginError`, `ValidationError`, `DataError`, `ProfileError`) with constructor signatures from A.5
- [ ] `Phantom.__init__(self, data_dir: str, in_memory: bool = False)` exists in `api/client.py`
- [ ] `Phantom` exposes attributes: `.accounts`, `.orders`, `.positions`, `.notes`, `.data`, `.brokers`, `.reports`, `.runner` (may be `None` or stub instances at this stage)
- [ ] All 8 sub-API stub files exist with their class defined
- [ ] `from phantom import Phantom` executes without `ImportError`
- [ ] `from phantom.errors import NotFoundError, ValidationError` works
